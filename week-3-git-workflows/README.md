# Overview
 This week upgrades existing Git knowledge to the collaboration and automation patterns used in real DevOps environments. The focus is on trunk-based development, commit discipline, and PR workflows — the habits that CI/CD pipelines and remote teams depend on.

# Key Concepts

 Trunk-based development — short-lived branches, frequent merges to main
Conventional Commits — feat:, fix:, docs:, chore: prefixes for readable history
PR discipline — writing descriptions that explain why, not just what
Git for ops — tagging releases, stashing, reading history, .gitignore hygiene


# Deliverable

- Proper .gitignore
- README.md written as a runbook
- Meaningful commit history using Conventional Commits
- At least one branch → PR → merge cycle visible in history
- v1.0.0 tag on the working state
